# 会员到期提醒功能测试文档

## 一、测试概述

### 1.1 测试目标

验证会员到期提醒功能的完整流程，包括：
- 用户提醒设置（启用/禁用、渠道选择、提前天数）
- 到期用户扫描（按日/周/月周期）
- 提醒记录创建（避免重复发送）
- 预警消息发送（多渠道推送）
- 提醒记录查询

### 1.2 测试覆盖场景

| 场景编号 | 场景名称 | 测试内容 |
|---------|---------|---------|
| 场景一 | 用户设置提醒配置 | 新用户默认设置、自定义设置、关闭/启用、更新设置 |
| 场景二 | 扫描到期用户并创建提醒记录 | 范围内用户、范围外用户、已关闭提醒用户、特定渠道用户 |
| 场景三 | 避免重复发送 - 幂等性保证 | 同一用户同一时间同一渠道、同一用户不同时间 |
| 场景四 | 发送提醒消息 | 状态更新、已发送不再重复发送 |
| 场景五 | 完整端到端流程 | 设置→扫描→发送→查询、关闭提醒不发送、批量处理 |
| 场景六 | 边界情况测试 | 不存在的用户、空渠道、无效渠道 |

### 1.3 测试文件

| 文件路径 | 说明 |

### 2.2 Docker 环境问题解决方案

#### 问题现象

在 macOS Docker Desktop 环境下，Testcontainers 可能无法找到 Docker 套接字，报错：
```
Previous attempts to find a Docker environment failed. Will not retry.
```

#### 问题原因

Docker Desktop for Mac 的 Docker 套接字位置：
- **实际位置**：`~/.docker/run/docker.sock`
- **默认查找位置**：`/var/run/docker.sock`

#### 解决方案

**方案一：创建符号链接（推荐，需要管理员权限）**

在终端执行：
```bash
sudo ln -sf ~/.docker/run/docker.sock /var/run/docker.sock
```

**方案二：配置 Docker Desktop 设置**

1. 打开 Docker Desktop
2. 进入 **Settings → Advanced**
3. 启用 **"Allow the default Docker socket to be used"** 选项
4. 点击 **Apply & Restart**

**方案三：使用环境变量**

在运行测试前设置环境变量：
```bash
export DOCKER_HOST=unix:///Users/<your-username>/.docker/run/docker.sock
mvn test
```

**方案四：配置 Testcontainers 属性**

已在项目中添加 `src/test/resources/testcontainers.properties`：
```properties
docker.client.strategy=org.testcontainers.dockerclient.UnixSocketClientProviderStrategy
testcontainers.reuse.enable=false
```

#### 验证 Docker 环境

执行以下命令验证 Docker 是否正常工作：
```bash
docker run --rm hello-world
```

如果能正常输出 hello-world 容器的欢迎信息，说明 Docker 环境正常。

## 六、常见问题排查

### 问题 1：Testcontainers 无法连接 Docker

**错误信息**：
```
Previous attempts to find a Docker environment failed. Will not retry.
```

**解决方案**：
1. 检查 Docker Desktop 是否运行
2. 执行 `docker ps` 验证 Docker 正常
3. 如果是 macOS，创建符号链接：
   ```bash
   sudo ln -sf ~/.docker/run/docker.sock /var/run/docker.sock
   ```

### 问题 2：数据库连接失败

**错误信息**：
```
HikariPool$PoolInitializationException: Failed to initialize pool
```

**解决方案**：
1. 检查 Testcontainers 是否正常启动 PostgreSQL 容器
2. 检查 `application-test.properties` 配置
3. 确认使用 `jdbc:tc:postgresql:15:///test` 格式的 URL

### 问题 3：测试数据冲突

**解决方案**：
- 每个测试使用唯一的用户 ID（`nextUserId()`）
- 测试之间数据隔离
- 使用 `@Transactional` 或手动清理数据

### B. 数据库表结构

**member_reminder（提醒记录表）**：
```sql
CREATE TABLE member_reminder (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    remind_time TIMESTAMP NOT NULL,
    channel VARCHAR(20) NOT NULL,
    status VARCHAR(20) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (user_id, remind_time, channel)  -- 防重放唯一索引
);
```

**user_reminder_setting（用户设置表）**：
```sql
CREATE TABLE user_reminder_setting (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL UNIQUE,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    channels VARCHAR(100) NOT NULL DEFAULT 'SMS,EMAIL',
    days_before_expire INT DEFAULT 7,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

| `member.reminder.batch-size` | `100` | 每批处理数量 |
